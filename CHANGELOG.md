## [2.0.0] — 2026-09-03

Кроссплатформенность и установка в три команды.

### Добавлено
- Работа на Linux и Windows, не только на macOS: хранилище секретов выбирается
  автоматически — Keychain, `secret-tool` (Secret Service) или файл `0600`.
  Форсируется через `YANDEX_MCP_KEYSTORE`, отдельный секрет можно прокинуть
  через `YANDEX_MCP_SECRET_<ИМЯ>` (для Docker и CI).
- Команды `yandex-mcp setup | login | status | logout`. `setup` проводит по
  шагам регистрации приложения Яндекса, `login` открывает браузер и ловит
  redirect на localhost.
- Единый вход: одна авторизация на Метрику, Вебмастер и Директ вместо трёх
  отдельных. Права запрашиваются все сразу — что реально доступно, определяют
  настройки приложения на oauth.yandex.ru, а не флаги CLI. Если `direct:api`
  не одобрен, `login` понимает это по ответу Яндекса, автоматически входит без
  Директа и сообщает, что повторный `login` подхватит его после одобрения.
  `login --service <имя>` по-прежнему выдаёт узкий токен на один сервис, и он
  имеет приоритет над общим.
- Инструменты `direct_report` (Reports API v5 — расход, клики, CTR),
  `webmaster_indexing`, `webmaster_sitemaps`, `metrika_compare`.
- Пакет ставится из PyPI: `pipx install yandex-mcp`.
- CI гоняет тесты и smoke-проверки на Linux, macOS и Windows.

### Изменено
- **Ломающее:** пакет `yandex_oauth` переехал в `yandex_mcp.auth`, отдельная
  команда `yandex-oauth` убрана — всё делается через `yandex-mcp`.
- **Ломающее:** записи в хранилище переименованы под единый префикс
  `yandex-mcp-` (`yandex-mcp-token`, `yandex-mcp-metrika-token`,
  `yandex-mcp-client-id`) вместо прежнего разнобоя `yandex-token` /
  `yandex-metrika-token` / `yandex-oauth-client-id`. Миграции нет: выполните
  `yandex-mcp setup` и `yandex-mcp login` — с новым входом это полминуты.
  Старые записи остаются в хранилище нетронутыми, их можно удалить вручную.
- `client_secret` больше не обязателен — используется PKCE. Если секрет лежит
  в хранилище (агентские приложения, старые установки), он всё ещё применяется.
- `client_id` берётся из `YANDEX_MCP_CLIENT_ID` или из хранилища.
- Метрики целей в `metrika_summary` запрашиваются пачками, а не по одной на
  цель — было N+1 обращений к API.
- Код переехал в `src/`-layout.

### Исправлено
- Windows: stdio принудительно переводится в UTF-8 — иначе сервер падал
  `UnicodeEncodeError` на первом же ответе с кириллицей.
- `metrika_summary` падал `IndexError` на цели без достижений за период.
- Вход падал трейсбеком, если oauth.yandex.ru отвечал не-JSON телом (например
  HTML-страницей ошибки от прокси) вместо понятного сообщения.
- `wordstat_phrases` падал `TypeError` на уточнении без поля `Shows`, а сбой
  при удалении отчёта мог потерять уже полученные данные.

## [1.0.0] — 2026-08

Первая версия: MCP-сервер к Метрике, Вебмастеру и Директу, macOS-only,
токены в Keychain, запуск из клона репозитория.
